新的关键路径是：检测确认 → SQLite 提交 → MQTT → 后端校验/事务提交 → 业务 ACK → 清理待发。浏览器通过 HTTP 查询业务结果，生产路径不再使用旧页面 MQTT 聚合器和旧 `sendMsg.py`。

实时检测不会把每帧图像和全量框写入业务数据库。同一轨迹首次建一条业务告警，普通快照默认至多每秒一次（类别变化另行发送），后续更新该告警；接收审计记录仍会随快照增长，尚无自动长期归档，不能把限频描述为解决了存储生命周期。

## 2. 恢复与一致性细节

**ACK 与失败。** MQTT PUBACK 只说明协议层接收，不能删除本地事件。后端成功提交才返回 APPLIED；数据库提交失败不返回成功。应用 ACK 丢失时相同 eventId、相同内容重投，业务唯一键保证不会重复创建。REJECTED 单独保存原因和原始内容，不能作为成功告警计数；管理员可查询 `/monitoring/rejections`。

**状态和容量。** 待发默认最多 10,000 条/64 MiB，单条 16 KiB；队列满或磁盘写失败明确暴露故障，已有待发保留。不是无限离线存储。检测失败/租约过期停止监测并标记中断，后端根据持久配置重试。控制含有效期、代次、会话；旧控制不能复活已停止任务。

**跟踪重启。** 工作进程不能再次启动已经使用过的服务器会话。强杀后本地 SORT 编号可能重置，必须申请新会话；旧会话告警标记 INTERRUPTED，新会话可以创建新告警。这避免错误合并，但不解决跨遮挡/跨重启的物理目标身份连续性。

**迟到和人工处置。** 结束快照可先到，低版本不会覆盖；已中断会话的迟到 ACTIVE 快照仍呈现 INTERRUPTED。设备和异常事件采用软删除；设备退役不清除待发事件核验所需的来源。监测启用期间禁止原地更换视频源，需先停用。自动更新不改人工处理人、处理结果和处理状态；人工分类覆盖与 detected_type 分别保存。

**错误信息。** 对类别 ID/名称、范围、时区、边框、会话归属和累计证据做严格校验；同 eventId 不同内容隔离。格式正确但模型识别错误的数据仍可能通过，不能从业务校验推断真实物体类别。初始告警是 1 级“待核验观察”，不把模型置信度解释为事故严重程度。

**时间。** 协议使用 UTC 带时区时间；新 first_seen/last_seen 存 UTC，兼容旧 event_time 的上海本地语义。Python 3.8 已兼容 Java 纳秒 ISO 时间。实时流当前使用接收/处理链路时间，不宣称硬件采集时间精度。

**安全边界。** 未登录 401，越权或 CSRF 错误 403；处理人取登录身份。口令、角色、状态变更使旧会话/预览授权失效，账户变更串行防止并发重置复用安全版本。用户响应不含口令哈希，摄像头响应不含 RTSP 凭据。密码 DTO 和摄像头源地址不进入 Lombok toString。公开注册已关闭，管理员重置随机临时口令且必须修改。浏览器没有 MQTT 服务凭据。

预览通过首条 WS 消息认证，不在 URL 放令牌；服务器解析视频源，忽略客户端源地址。每个观看连接独立管理流，最长约 15 秒复核一次有效授权。MQTT 重连后的订阅由后台调度执行并重试，避免已连接却因一次订阅超时长期收不到数据。部署配置将后端、Flask、媒体入口和 Broker 管理端口限环回，Nginx 对外屏蔽内部预览接口；跨主机 MQTT 要求 TLS 与正确主机名证书。

| Flask 授权与连接隔离 | 5 项通过 |
