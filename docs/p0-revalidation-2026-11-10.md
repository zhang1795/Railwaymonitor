# P0 完整复验、补修与当前结论

日期：2026-11-10（Asia/Shanghai）。范围为原交付审查 R01–R06，未开始 P1 算法或容量改造。

**结论：初测仍有遗漏，不能沿用上次“已有测试全部通过”直接判定 P0 结束。** 本轮补充用例复现了人工操作并发写回、异常时间接收、空字体缓存启动失败三处问题，已补修并复测。修复后的实现，在下面明确覆盖的故障与访问边界内通过 P0 门槛，可以继续处理 P1；这不代表项目已达到生产交付验收标准。

本轮还因未提前隔离正在运行的 jar 与构建目录，引发过一次本机升级中断。这是本次测试操作的疏漏，单独记录在第 4 节，没有将其隐藏在“最终通过”后面。

## 1. 新发现与修复

### F01：人工操作会恢复过时的自动检测信息

原实现先读取完整异常实体，再用 `updateById` 写回完整实体。确定的执行顺序为：

1. 人工请求读取 ACTIVE / 工人 / 0.30。
2. 自动接收提交 ENDED / 牛 / 0.95。
3. 人工请求把先前实体写回，检测状态、自动分类、置信度等随之倒退。

“处理事件”“编辑事件”“修改处理状态”三个入口均在 **H2 和真实 MySQL** 复现，结束状态被写回 ACTIVE。此前测试验证了自动更新不覆盖人工处置，漏测了反向覆盖。

补修：[AbnormalEventServiceImpl](../web-springboot/src/main/java/com/example/service/impl/AbnormalEventServiceImpl.java) 三个入口只更新各自拥有的人工字段，不再写回读取到的自动检测字段；并发删除导致更新失败时明确返回冲突。

验证：测试专用 MyBatis 调度钩子在人工读取后暂停请求，提交最新检测，再放行人工写入；三个入口均保留 ENDED、牛、0.95 和对应人工结果。钩子只在测试中注册，不进入生产包。

### F02：时间“可解析”不等于时间信息可接受

`0001-01-01T00:00:00Z`，以及转换为 UTC 后越过项目支持下界的时间，原先都会得到 APPLIED；H2 和真实 MySQL 均已复现。旧校验没有明确的支持范围，也没有把实时观测与服务器保存的监测会话时间联系起来。

补修：[DetectionIngestService](../web-springboot/src/main/java/com/example/detection/DetectionIngestService.java) 统一在 UTC 下校验支持范围；`received_at` 还须落在会话创建/结束的容差窗口内（60 秒）。异常数据持久隔离并返回 REJECTED。`media_time` 的历史媒体时间与实时会话时间分别处理，避免错误拒绝合法回放。

验证包含：无时区、超范围、时区转换越界、会话创建前一小时、结束后过远的观测、合法历史媒体时间，以及类别、置信度、边框、sequence 和累计证据等反例。它仍不能证明设备报告的时间就是硬件采集时间。

### F03：空缓存下下载字体会阻断真实检测启动

在全新缓存目录启动真实 YOLO 时，绘图模块导入会尝试下载 Arial 字体；本轮下载收到 HTTP 308，工作任务进入 FAILED，无法产生告警。此前真实模型检查复用了已有字体缓存，掩盖了这个冷启动依赖。

补修：[plots.py](../RailwayDetector/utils/plots.py) 删除导入时的字体加载/下载，不在检测进程中自动下载字体或安装 Pillow；需要字体时优先本地指定字体、缓存字体、DejaVu，再使用 Pillow 默认字体。

验证：空缓存并禁止下载的回归由失败转为通过；随后在另一全新缓存目录完成真实模型、RTSP、告警入库及双观看连接的组合验收。完整中文图片叠字的字体资产质量仍需单独配置，检测元数据不依赖它。

## 4. 本次升级中断与恢复

完整测试打包时，旧后端仍从 Maven `target/` 路径运行。我没有先隔离运行包，覆盖构建产物后，旧 JVM 在退出时发生 `ClassNotFoundException` / `NoClassDefFoundError`，本机升级未能在原等待窗口内完成。

这导致一路已启用监测超过控制租约，存在监测盲区。后端随后恢复，原启用配置及检测进程保留，该路按设计转入新会话继续运行；已持久待发清零，原 84 条历史记录保留。**不能把补传成功表述成这段期间没有监测中断。**

已补上 [stage_backend.py](../deploy/stage_backend.py)：按内容哈希生成独立、只读、原子发布的运行副本，服务与测试运行器均不再直接执行可被 Maven 覆盖的 `target` 包。4 项测试通过后，又实际执行打包：运行 PID 不变、页面与 API 可访问，运行包和最终构建的 62 个业务类字节码一致。

当前本机后端已加载并发/时间补丁。为保留正在运行的任务，没有再次重启检测进程；字体源码修复会在新进程启动时加载，已在独立空缓存进程验证。后端重启后浏览器需重新登录。

## 5. 可以推进 P1，但保留这些边界

- 当前本机使用显式的环回 HTTP/MQTT 验收模式。TLS 客户端与 ACL 在隔离 EMQX 验证，公网 Nginx/HTTPS、证书部署和生产网络配置尚未实机验收。
- 浏览器自动控制不可用；监控组件逻辑、真实 HTTP/WS 已测试，未做实际浏览器 DOM 点击、样式和地图可视化验收。
- 未做真实多路容量、长时间满载背压、24/72 小时稳定性或现场模型精度验收；并发正确性测试不是性能压测。
- 状态 API 中一个已停止任务仍保留旧的 `pending_events=1`，而本节点 SQLite 实际待发为 0。该字段是上次任务状态携带的节点采样，不能直接相加或当作实时积压；P1 的 R19 应补独立节点心跳、明确指标归属和过期标识。本轮清零判据读取实际 outbox，不依赖该旧采样。
- 鸟穿越遮挡、轨迹身份保持、ROI 风险规则、证据上传、真实通知、数据归档、进程守护/多节点高可用仍属于后续事项。这里只修了 R21 的字体冷启动依赖和 R18 的运行包隔离，不整体关闭 R07–R21。
- 可靠补传以事件已经持久提交、存储可恢复、容量未耗尽和身份/配置正确为前提；不能承诺磁盘永久损坏、节点永久丢失、模型漏检或持久化前崩溃时“绝对不丢”。

本次新增的隔离容器、网络和 MySQL 在验收后清理；本机业务服务继续保留运行。
