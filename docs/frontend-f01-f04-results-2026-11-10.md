## 未读的含义和正确性

新增 `alarm_notice_read` 保存**每个账号、每条告警**的已读回执。首次启用时，没有回执的历史告警也算未读；未读数量不是本次登录后新增数量，也不是未处理数量。

- 成功查看详情只标记这一条；“本批标为已读”只发送提醒面板当前展示的明确 ID。
- 已读不修改处置状态、处理人、检测状态或元数据。普通值班账号只能标记自己的已读，不能指定其他账号。
- 查询按账号回执排除，按 ID 倒序分页；`beforeId` 只用于翻阅，不是已读水位。较小 ID 的迟提交不会被“已经读到更大编号”吞掉。
- 数量和该页数据在一致性事务中读取；通知 ID 返回字符串，避免浏览器整数精度破坏身份。
- 退出/重新登录保留服务端回执；前端清理账号缓存、停止轮询，并拒绝旧登录的迟到响应。

提醒不自动判定真实风险，不替代 P1 的事发媒体、真实通知及人工处置闭环。大数据下的未读查询成本、回执归档和容量仍需 P1 压测。
