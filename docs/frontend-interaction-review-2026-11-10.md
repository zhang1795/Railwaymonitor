# 前端核心交互检查

日期：2026-11-10（Asia/Shanghai）。检查对象为 P0 补修后的当前工作区。

> 本文为修复前快照。F01–F04 后续已实现并更新本机版本；F05 媒体/核验信息与 F06 手工坐标降级后续也已补修，见 [P1 完整复验](p1-completion-results-2026-11-11.md)。真实浏览器与地图实景验收仍未完成。

**结论：仍有 6 类影响核心使用的大问题，不能仅凭 P0 链路测试通过就认为前端已具备交付条件。** F01–F05 为当前实现可以确定的问题；F06 为地图依赖失效时可复现的接入阻断风险，未判定当前地图服务已经失效。本轮只检查与复现，未修改业务实现、重启服务或变更现有监测任务。

检查覆盖登录/会话、整体导航、实时监控与播放器、摄像头管理、异常事件、用户管理、三个统计子页，以及关联地图、分页、请求与预览客户端。重点为操作能否完成、状态是否可信、告警能否被发现和核验；不列样式、图标、间距等细节。登录、用户管理、统计数据适配暂未发现与下面问题同等级的新阻断，不代表已完成这些页面的浏览器验收。

浏览器控制当前不可用，因此证据来自页面脚本执行、Vue 响应式效果验证、源代码检查和真实只读 API 核对；**没有实际浏览器点击、DOM 布局或地图可视化验收**。

## F01：停用后台检测的入口依赖设备在线及预览连接

**影响：设备或预览出问题时，管理员反而可能无法通过页面停用它的后台检测。**

监控页只有存在 `activeCamera` 时才显示后台检测按钮。但列表选择逻辑先检查设备状态，再检查预览 WebSocket，两者任一不可用都会提前返回，未设置 `activeCamera`。新进入页面且目标设备离线，或者预览网关不可用时，管理员无法选中该任务；摄像头管理页也没有独立的监测启停入口。

这还会阻断后续维护：后端按设计要求先停用监测才能删除设备或修改视频源，页面却缺少故障状态下的可达停用路径。曾经选中过该设备的页面可能仍保有按钮，本问题并非每次断流都会隐藏现有按钮。

证据：7 项复现检查中的 F01；[监控按钮](../web-vue/src/views/monitor/index.vue)第 24 行、选择逻辑第 449 行；[设备维护限制](../web-springboot/src/main/java/com/example/service/impl/CameraServiceImpl.java)。

修复要求：设备选择与预览打开分开；管理检测任务时可选择离线、故障设备，启停只依赖业务 API。设备管理提供明确的监测状态及停用入口。

验收：保持业务 API 可用，分别模拟设备离线、预览网关断开；新登录管理员均能选中并停用指定任务，其他任务不受影响。

## F02：失联后仍显示“检测中”，状态缺少有效期

**影响：值班人员可能把过时的运行状态当作当前监测正常。**

监控页每两秒读取任务状态，但只展示状态枚举，没有使用接口已经返回的 `last_status_at`、`error`。旧的 RUNNING 样本也直接映射成“检测中”。后续请求失败时保留原标签，无状态过期标识；全局请求拦截器可能弹网络错误提示，但不能让该设备标签失效。

复现：输入很早的 RUNNING 样本后，连续十次查询失败，页面状态仍为“检测中”。这是显示可信度问题；后台租约和恢复逻辑并不能替代前端的新鲜度判断。

证据：[状态轮询](../web-vue/src/views/monitor/index.vue)第 544 行；接口及工作节点状态记录见 [MonitoringService](../web-springboot/src/main/java/com/example/detection/MonitoringService.java)。

修复要求：分别展示启用意图、节点报告状态、报告时间和通信状态；查询失败或报告过期时显示“状态未知/报告过期”，保留最后一次信息并标注时间；失败原因可查看。不能由页面推测失联期间实际执行了多少次检测。

验收：正常运行后切断状态查询，达到约定有效期后不得继续以有效“检测中”状态展示；恢复后重新确认，停止状态也按其采样含义展示。

## F03：预览中断可能保留旧画面，“重试”无法恢复断开的连接

**影响：静止的旧画面可能被误认为实时画面，故障后的恢复操作也不完整。**

有三处相关缺口：

- `wsClient.isConnected()` 返回普通对象字段，未接入 Vue 响应式状态。监控页把这个方法的结果作为播放器 `isActive`，连接变化本身不会触发重新渲染，后续偶然的页面更新不能作为可靠通知机制。
- 播放器的 15 秒超时只覆盖启动期，`stream_ready` 后清除；没有最后一帧时间或持续断帧检测。网络中断且收不到 `camera_status` 时，最后一帧和原“在线”标记可能一直保留。
- 播放器 `retryConnection()` 在 WebSocket 已断开时直接返回，不会调用客户端重连。纯断流还可能根本不出现错误覆盖层。

复现：一帧及 ready 后模拟失联，推进 120 秒，画面未清除、错误状态未出现、设备仍显示在线；调用重试没有新命令或重连动作。另用真正的 Vue `effect` 执行生产 WebSocket 客户端，认证成功与断开均未使读取连接状态的效果重新执行。

证据：[播放器](../web-vue/src/components/VideoPlayer/index.vue)第 67、130、254、316 行；[连接客户端](../web-vue/src/utils/websocket.ts)第 20、94、243 行；[父页绑定](../web-vue/src/views/monitor/index.vue)第 38 行。

修复要求：提供响应式连接状态和统一的预览生命周期；显示最后帧时间，断帧后明确覆盖“画面已过期”；重试先恢复授权连接，再确认目标流收到新帧。预览恢复不得变更后台检测启用配置。

验收：观看中断网及恢复、预览服务重启、自动重连耗尽后手工重试，均能识别过期画面并恢复；同时保持已验证的两观看连接隔离及后台检测独立性。

## F04：新告警不会主动进入值班人员当前页面

**影响：后台已可靠入库，值班人员仍可能长期不知道发生了新告警。**

异常事件页仅在进入页面、查询/翻页、人工操作后重新拉取。没有自动刷新或新告警提示。监控页只轮询检测任务状态，没有告警列表、未读提示或告警跳转；全局布局和首页也未提供告警提醒。统计概览的近期告警同样依赖进入或手工刷新，且只对管理员开放。

复现：异常事件页首次加载后，内存服务新增告警，模拟经过 60 秒，页面请求仍只有一次、列表仍为旧记录；手工查询后才能看见新增记录。真实接口于本轮核对时已有 319 条事件，后台摄像头 22 为 RUNNING；这份快照仅证明真实数据存在，不是通知时延测量。

证据：[异常事件列表与挂载](../web-vue/src/views/Abnormal/index.vue)第 311、568 行；[监控轮询](../web-vue/src/views/monitor/index.vue)第 544 行；[全局布局](../web-vue/src/components/Layout/index.vue)。

修复要求：在全局提供新告警数量和可跳转入口；可先采用有游标/稳定排序的增量轮询，再按需要引入推送。存在新数据时提示用户，避免把正在编辑、筛选或处置的页面直接冲掉；重新连接时能补查遗漏。此项也对应原 R14 通知闭环缺口，真实短信仍需另行实现。

验收：普通值班账号停留在监控页和异常页时都能在约定时间内发现新告警；断网恢复补齐；浏览器告警提示失败不影响后台落库。

## F05：告警详情没有提供足够的核验信息

**影响：工作人员难以判断检测到了什么、目标是否仍在，以及人工核验与自动判断是否发生分歧。**

后端已返回 `type`、`detectedType`、`confidence`、`detectionState`、`firstSeen`、`lastSeen`，但列表没有类别列，详情没有独立显示这些检测字段。页面主要展示人工处理状态，无法直接区分 ACTIVE、ENDED 和 INTERRUPTED。**“未处理/已处理”与“目标仍在/目标消失/检测中断”是两组独立信息。**

默认描述文本确实包含自动类别和置信度，不能说完全看不到类别；但描述可人工修改，且人工覆盖后自动更新不再改写该文本，因此不能替代独立的最新检测字段与核验类别展示。

证据入口也不足：标为“现场视频”的位置实际使用 `el-image`，没有录像播放器；本轮只读取得的最新 5 条真实告警均无 `imageUrl`。这部分涉及原 R13 媒体链路，单改前端不能生成不存在的证据，也不能拿当前直播代替事发录像。

证据：[列表及详情模板](../web-vue/src/views/Abnormal/index.vue)第 65–203 行；[真实接口快照](test-results/frontend-interaction-audit-2026-11-10/read-only-api.json)；[自动文本与人工覆盖规则](../web-springboot/src/main/java/com/example/detection/DetectionIngestService.java)第 165–184 行。

修复要求：列表可快速识别类别；详情同时显示自动类别/分数、人工核验类别、检测状态、首末时间和处理信息；媒体明确区分事发图片、事发录像、当前直播及“证据未生成/不可用”。完整媒体接入与 P1 R13 联动。

验收：同一告警从 ACTIVE 到 ENDED/INTERRUPTED、人工修正类别后又收到检测更新，页面仍能准确区分所有信息；无证据时明确说明缺失，不表现成视频播放功能已经完成。

## F06：地图不可用会阻断新增摄像头，缺少接入退路

**影响：第三方地图配置或访问失败，会使核心设备接入流程无法完成。**

新增摄像头必须先在地图选择经纬度，但表单没有手工录入坐标的入口；坐标为空直接拒绝提交。地图缺少密钥会直接返回，SDK 加载失败也没有恢复/降级处理。因此完整填写名称、位置、IP、RTSP 后，仍可能无法提交。

本机配置文件中两项地图配置均存在，**没有据此断言当前密钥失效或当前地图打不开**。风险在无外网、SDK 服务故障、密钥配置失效等条件下；已分别复现缺少配置和 SDK 拒绝加载两个分支，没有真实断开地图服务。

证据：[位置选择与提交门槛](../web-vue/src/views/camera/index.vue)第 123、358 行；[地图初始化](../web-vue/src/components/Map/index.vue)第 74 行。

修复要求：提供带范围校验的手工经纬度入口，明确坐标系；地图失败时保留表单并可继续基础接入。是否允许暂缺坐标应按业务规则决定，不能默认偷偷写入 `(0,0)`。

验收：屏蔽地图 SDK 或使用失效配置时，管理员仍能通过已验证的坐标录入方式接入设备，后续恢复地图不丢已填内容。

## 建议处理顺序与验证边界

先补 F01/F02/F03，使监测可控、状态可信、预览故障可见；然后处理 F04/F05，使告警可发现、可核验；F06 在设备接入流程中补降级入口。完整录像证据与真实通知应纳入 P1 对应链路，避免只改按钮或文案便判定闭环完成。

本轮结果：7 项缺陷复现检查均确认上述现象；既有当前监控组件 4 项、授权预览客户端 2 项仍通过；`vue-tsc -b` 与 Vite 生产构建通过。**复现检查通过表示问题被复现，不能解释为修复验收通过。** 证据和复跑说明见 [本轮证据目录](test-results/frontend-interaction-audit-2026-11-10/README.md)。

原 P0 后台持续监测、幂等入库、消息补传和访问控制结论不因本报告自动撤销；本报告补充的是前端在实际值班和故障操作中的交付缺口。尚未修改本报告中的六类问题。
