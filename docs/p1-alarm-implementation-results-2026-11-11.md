## 已实现的行为

### 1. 观察、风险与人工处置分开

未配置规则的摄像头记录 **待核验观察**，不自动推断铁路风险，也不发送周期性的持续风险提醒。管理员在摄像头管理中配置类别、图像矩形区域、当前置信度和停留时间后，满足条件才创建区域风险事件。区域按目标框底边中心判断，不使用历史最高分冒充当前分数。

| 参数 | 默认值 | 可配置范围/含义 |
| --- | --- | --- |
| 规则启用 | 关闭 | 必须明确选择类别并校准区域 |
| 当前置信度 | 0.5 | 0–1 |
| 连续符合规则 | 2 秒 | 0–60 秒；中断或类别变化会重新计时 |
| 短暂丢失容忍 | 3 秒 | 1–30 秒 |
| 持续提醒间隔 | 60 秒 | 10–3600 秒 |
| 初始规则等级 | 1 | 1–5；与人工记录等级分别保存 |
| 持续升级 | 180 秒 | 0–86400 秒；0 关闭，达到后最多上调一级至 5 |

这些是工程默认值，需要现场标定，不是铁路安全阈值或告警延迟承诺。规则仅在停用该路检测后修改，带版本检查，下次检测会话固定使用一份规则快照。

风险状态为 PRESENT（持续）、MISSING（暂未见，等待确认）、CLEARED（观测确认不再满足风险条件）、INTERRUPTED（监测中断，状态未知）。检测原始状态、风险状态、账号已读、人工处理结果分别记录。停机、断流、失去会话不能当作风险解除；超过 35 秒没有新观测时页面会显示当前状态未知。

### 2. 时间型失踪处理与有限续接

检测快照 v4 新增 MISSING、`observedThrough`、`missingSince`，仍通过既有 v3 MQTT 主题传输。跟踪超时按有效观测时间而非固定两帧计算，卡尔曼预测使用时间差。出现长时间处理间隔后的一张空帧只开始缺失确认，不能立即宣告目标消失；尚有相容未确认检测时保留“身份不确定/观测中断”。

业务层只在同摄像头、同会话、相同自动类别、3 秒默认窗口内、归一化 IoU 至少 0.3 且候选唯一时续接。已有可见目标、多个候选、远距离或跨会话均不盲目合并。续接保留多条来源记录；目标离开规则区域并满足解除条件，再进入时产生新事件，即使 trackId 没变。

每条来源继续使用递增序号、事务幂等和会话约束。乱序旧快照不能重新打开已结束事件或回滚较新自动类别。若终止/缺失快照先到而缺少前序风险判定依据，只建立“前序不完整、待核验观察”，不补造停留历史或物理身份。

### 3. 同一风险一分钟内如何提醒

假设已配置风险规则、已完成停留判定，并持续收到新鲜实时观测：

- 触发时：1 条业务事件 + 1 条 FIRST 首次提醒。
- 风险持续满 60 秒：同一业务事件新增 1 条 ONGOING 提醒；默认之后每个 60 秒区间最多一条。
- 风险达到升级条件：新增 ESCALATION 提醒，不覆盖原人工等级或处置。升级那次观测优先写升级提醒。
- 已读 FIRST 或人工已处理，不消耗后续提醒；人工结果保留，页面提示持续存在需复核。
- 已解除后再进入、关联证据不足或跨会话，可能产生新的业务事件，不能承诺“同一个物理目标永远只有一条”。

提醒写入独立表，唯一键限制同事件/类型/时间区间重投。回执绑定账号与具体 `noticeId`；打开详情只确认该次响应实际返回的未读提醒 ID。无新鲜实时观测、旧消息补传或历史文件回放不会凭计时器生成持续提醒，也不补发断连期间所有时间区间。

### 4. 截图与详情

详情展示自动类别及其最高分、人工编辑字段、风险规则与版本、轨迹关联、首末观测、状态变化、提醒历史和人工操作审计。历史截图标明采集时间，实时预览不能代替历史证据；完整录像明确显示未上传。

截图走独立 SQLite WAL 持久队列，默认最多 500 项/64 MiB；文件权限 600，媒体失败不撤销关键元数据。队列重启保留待发项，元数据尚未提交返回 425 后重试。截图最多 640×480，每来源最多每 2 秒采样一次；服务端每事件最多保留 3 张。超过限制不会增加关键告警积压。

上传使用独立服务密钥和工作节点身份，预览密钥、浏览器 Origin 或错误节点无法替代。服务端只接收已入库且来源匹配的实际 ACTIVE 观测，限制单张 2 MiB/解码像素，并按事件序号绑定对应事件。受控本地目录默认总配额 1 GiB，含孤立文件；写入执行 fsync、原子发布、SHA-256 校验。读取要求用户登录且事件/资源绑定正确，逻辑删除事件不再提供访问。

队列积压、跳过与错误分别可见；配额满时截图保留待发并重试，关键告警仍保留。完整视频、对象存储、自动保留期/归档和短信送达尚未完成，不能将本批截图支持解释为完整媒体生命周期。
