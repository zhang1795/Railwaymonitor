# 统计趋势时间轴修复

2026-11-11。用户截图中的日期在 2025/2026 年间来回跳转，真实统计接口也确认返回了未排序的 9 个日期分组。

原因：后端按创建日期分组后从无序 Map 生成列表；异常统计页直接将这些日期按返回顺序放进分类轴。日期因此乱序，跨天和跨月还被显示成相同间距。此次仅修复前端，不重启后端或检测节点。

改动位于 [AbnormalEvent.vue](../web-vue/src/views/statistics/AbnormalEvent.vue)：

- 按日期升序处理，日期与计数一起移动，不修改共享接口响应。
- 使用真实时间轴和明确的日历日期编码，避免浏览器时区使日期偏移。
- 没有入库记录的日期按 0 显示；长空档只增加两端零点，避免跨多年数据产生巨大数组。折线取消平滑，避免制造日计数间的虚假曲线。
- 增加缩放滑块和区域缩放，便于检查跨度较长的历史数据。
- 刷新复用图表实例，阻止重复请求；离开页面后不再让迟到响应创建图表。
- 对齐统计响应的 TypeScript 字段定义。

仍使用原统计接口按 `createTime` 分组的口径，没有修改历史记录、统计日期或事件数量；零表示该日期没有入库计数，不代表风险不存在。后端响应本身仍不承诺顺序，页面负责按时间绘制。

验证：

- [4 项回归](../web-vue/tests/statistics-timeline.test.cjs) 使用真实 ECharts SVG 渲染，覆盖截图日期及计数绑定、真实日期间距、闰日/长空档、单日/空数据刷新、实例复用与迟到响应。
- 分别在 Asia/Shanghai 和 America/Los_Angeles 时区运行，全部通过；类型检查和 Vite 构建通过。
- 经 3000 页面代理登录读取真实统计接口，分组计数合计与总数一致；确认 Vite 已提供新组件，前端/后端/检测 PID 文件均未变化。检查后退出独立验证会话，没有修改真实告警已读或处置。
- 浏览器控制宿主不可用，未声明实际浏览器点击或布局验收。

私有日志位于 `workspace/runtime/statistics-timeline/`。当前本机使用 Vite，刷新“异常事件统计”页面即可加载修复；生产静态部署需发布重新构建的 dist。
