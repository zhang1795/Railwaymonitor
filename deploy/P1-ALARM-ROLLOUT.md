# P1 告警版本切换

适用于已完成 P0 与 F01–F04 迁移的单后端/单检测节点环境。功能及验证边界见 [本批报告](../docs/p1-alarm-implementation-results-2026-11-11.md)。现有服务不从源码重新读取 Java/Python 模块，修改源码或构建完成不表示运行版本已经更新。

## 前置准备

1. 核对当前后端/节点 PID、运行包、工作目录、实际端口、全部摄像头启用状态与会话，并确认操作的是项目数据库。本机实际业务库 3307，隔离测试 13317，另一项目占用 8080，不得替换。
2. 保存业务库完整逻辑备份、私有 `.env`/`.env.p0`、进程参数/环境和 SQLite 一致性备份。对运行中的 WAL 数据库使用 SQLite backup API，不能只复制主文件。记录原始历史行数和任务状态；备份目录 700、文件 600，不提交 Git。
3. 构建并执行本批测试，将 jar 通过 `stage_backend.py` 固化、检测源码/配置通过 `stage_detector.py` 固化。模型权重使用明确的绝对路径，不从构建目录运行长驻进程。
4. 新增独立随机 `EVIDENCE_SERVICE_KEY`（至少 32 字符），只给业务后端与对应检测节点。`EVIDENCE_INGEST_URL` 应指向正确的 `/api`，本机为 `http://127.0.0.1:18080/api`；跨主机必须使用可信 HTTPS，可通过 `EVIDENCE_CA_FILE` 指定 CA。`EVIDENCE_ROOT` 指向可持久备份的受控目录，`EVIDENCE_MAX_BYTES` 默认 1073741824。密钥不能与 `PREVIEW_SERVICE_KEY` 共用，不能给前端或 Flask。

当前 Nginx 模板拒绝公网 `/_evidence` 和 `/api/_evidence`；跨主机上传需单独提供受控的 HTTPS 内部入口。浏览器用户通过正常业务 API 登录读取，不获得服务上传密钥。本批使用本地文件目录，不需要引入 MinIO，也不需要重新构建 EMQX/MediaMTX 镜像。

## 切换顺序

1. 对正确业务库执行 [p1-alarm-migration.sql](../web-springboot/src/main/resources/db/p1-alarm-migration.sql)。该文件为新增表及 `INSERT IGNORE`，支持重复执行；不要重跑旧 P0 的 ALTER 迁移、不要执行全量初始化 SQL。
2. 在旧后端仍在线时可先建表；停旧后端并确认退出后，再完整执行一次 P1 迁移，补齐首次提醒种子，避免切换准备期间新增的旧版本告警没有 FIRST 提醒。已有旧“已读”只迁移到 FIRST 回执，不消耗未来持续提醒。
3. 启动新不可变 jar，核对 schema、端口、登录、监测查询与 MQTT。若后端就绪失败，停止新实例，再恢复已保存的旧不可变 jar；本迁移为附加表，不直接删除新表或恢复整库覆盖切换期间数据。后端未就绪前保留原检测进程，由原 outbox 等待业务确认。
4. 新后端就绪后，对检测进程发 SIGTERM 并等待退出；不得同时运行两个相同 workerId/outbox 的节点，也不强行绕开文件锁。保留原事件 SQLite 与控制代次，启动新不可变 Python 版本，使用原输出目录、绝对模型路径和新证据配置。首次确认新进程实际收到新会话、原启用摄像头恢复 RUNNING 后，再判定恢复。
5. 发布前端 dist 或更新开发页面。当前本机 Vite 直接读取源码，应在后端配套切换完成后刷新页面、重新登录。规则默认关闭，不能替用户猜测现场区域和风险类别。

节点重启会切换会话并短暂停止检测，需要记录实际中断/恢复。历史物理身份不能跨会话自动合并。只有此前已保存完整旧源码/配置及模型运行约束时，才能声称 Python 源码可回退；本机本次是首次固化 Python 版本，旧进程加载过的源代码没有可验证副本。若新节点异常，应保留待发与故障证据并修复，不能把进程启动或 API 就绪当作检测恢复。

## 切换后验收

- 全部原摄像头启用意图不变；停用摄像头不被自动启用，原启用摄像头实际运行并有新有效观测。保存新 PID、会话、代次和恢复耗时。
- 原始历史记录数量/人工处置保留，迁移前后的业务行数合理；不修改真实用户已读/处理数据用于测试。
- 匿名 API/图片访问拒绝；登录后可查询规则、详情、提醒与匹配截图；检查截图校验和与捕获时间。完整视频状态仍为未上传。
- 关键 outbox 与截图待发、拒绝记录及错误可查，继续无浏览器入库；跨主机确认 TLS/ACL 与证书校验。本机 HTTP/MQTT 联调不是对外生产配置。
- 风险规则交互：管理员先停用检测，校准区域/类别/参数并保存，再启用检测。不要为了展示新提醒而擅自改现有摄像头规则；在隔离环境验证 60 秒连续风险、已读和人工处理后再提醒。

本机一次性脚本在私有 `workspace/runtime/p1-alarm/apply_p1.py`，生成私有 `workspace/runtime/p1-rollout/20261111-alarm/` 并拒绝覆盖已有记录。2026-11-11 的首次停服切换命令曾被自动审批审查拒绝；用户明确同意后已经执行成功，并通过切换后检查。该脚本已产生记录，不能原样重复运行；后续发布应准备新的备份目录和明确的源/目标版本。
